Tools Reference

Complete specification for all 12 deterministic Failures MCP tools.

get_principles() DISCOVERY

Returns all 11 failure dimensions, invariants, questions, applicable systems, and mitigation patterns. Supports keyword filtering.

ParameterTypeDescriptionRequired
filterstringOptional search string (e.g. 'timeout', 'payment')No
Example Input & Output 
// Input
{"filter": "idempotency"}

// Output
{"principles": [{"id": "idempotency", "name": "Idempotency", "severity": "CRITICAL"}]}

review_architecture() ANALYSIS

Analyzes full system descriptions, components, flows, and dependencies. Detects network boundaries, multi-write flows, and surfaces severity-ranked vulnerabilities.

ParameterTypeDescriptionRequired
systemstringDescription of the system architectureYes
componentslistList of component names or objects with dependenciesNo
flowslistList of critical request pathsNo
Example Input & Output 
// Input
{"system": "Checkout API with FastAPI, PostgreSQL, and Stripe"}

// Output
FAILURE REVIEW — [CRITICAL] External side-effect without idempotency key

analyze_component() ANALYSIS

Deep dives into a single architectural component (database, queue, payment, cache, auth, storage, worker).

ParameterTypeDescriptionRequired
component_typestringpayment | database | queue | cache | auth | worker | storageYes
descriptionstringWhat this specific component doesYes
Example Input & Output 
// Input
{"component_type": "payment", "description": "Debits credit cards via Stripe"}

// Output
COMPONENT REVIEW — [CRITICAL] External charge before DB transaction

review_code() STATIC CHECK

Deterministic static AST & regex analyzer for source code. Surfaces failure risks, code evidence excerpts, confidence scores (0.0 - 1.0), and required controls.

ParameterTypeDescriptionRequired
codestringSource code snippet to reviewYes
languagestringpython | typescript | goNo
Example Input & Output 
// Input
{"code": "await stripe.charge(); await db.execute()", "language": "python"}

// Output
STATIC FAILURE CHECK — [CRITICAL] External side-effect without idempotency key (Confidence: 0.91)

review_plan() PLANNING

Inspects ordered implementation steps BEFORE any code is written. Catches ordering bugs like charging before writing pending state.

ParameterTypeDescriptionRequired
featurestringFeature or user story descriptionYes
planlistOrdered list of step descriptionsYes
Example Input & Output 
// Input
{"feature": "Checkout", "plan": ["1. Charge Stripe", "2. Save order to DB"]}

// Output
PLAN REVIEW — [CRITICAL] Step 1 executes external side effect before local state

check_invariant() VERIFICATION

Validates whether stated engineering invariants can be violated by failure scenarios in a given architecture, plan, or codebase.

ParameterTypeDescriptionRequired
invariantslistList of predicate statements that must hold trueYes
Example Input & Output 
// Input
{"invariants": ["payment.never_double_charged"]}

// Output
INVARIANT CHECK — [VIOLATABLE] payment.never_double_charged under retry timeout

check_idempotency() SAFETY CHECK

Dedicated verification on whether an endpoint or function is safely repeatable.

ParameterTypeDescriptionRequired
codestringCode implementationYes
Example Input & Output 
// Input
{"code": "def process_order(): db.insert(order)"}

// Output
IDEMPOTENCY CHECK — NOT_IDEMPOTENT (Missing unique key)

check_retry_safety() SAFETY CHECK

Evaluates whether adding retries to a code block will amplify failure or create duplicate side effects.

ParameterTypeDescriptionRequired
codestringCode implementationYes
Example Input & Output 
// Input
{"code": "@retry(times=3)\nasync def charge(): stripe.charge()"}

// Output
RETRY SAFETY — UNSAFE_FOR_RETRY (Non-idempotent operation retried)

check_transaction_safety() SAFETY CHECK

Analyzes database queries and transactions for partial commits, missing rollbacks, and lost updates.

ParameterTypeDescriptionRequired
codestringCode implementationYes
Example Input & Output 
// Input
{"code": "await db.execute(\"UPDATE accounts...\"); await db.execute(\"UPDATE orders...\")"}

// Output
TRANSACTION SAFETY — UNPROTECTED_MULTI_WRITE

generate_failure_cases() GENERATION

Generates concrete, actionable failure scenarios tailored to your system stack.

ParameterTypeDescriptionRequired
systemstringSystem architecture descriptionYes
Example Input & Output 
// Input
{"system": "Order fulfillment with RabbitMQ and Postgres"}

// Output
FAILURE CASES — [HIGH] Worker crash between message processing and queue ACK

generate_failure_tests() GENERATION

Generates concrete pytest / jest test definitions covering chaos and failure modes.

ParameterTypeDescriptionRequired
systemstringSystem descriptionYes
Example Input & Output 
// Input
{"system": "FastAPI Stripe Checkout"}

// Output
FAILURE TESTS — test_retry_after_provider_timeout, test_db_crash_after_charge

list_failures() DISCOVERY

Lists the full static rule dictionary and failure documents from the internal knowledge base.

ParameterTypeDescriptionRequired
filterstringOptional filter stringNo
Example Input & Output 
// Input
{"filter": "concurrency"}

// Output
{"rules": [{"id": "race_condition_read_modify_write", "severity": "HIGH"}]}
